# Offline Kokoro Mandarin playback on Windows

## Goal

Let Windows learners hear selected Mandarin text in an existing LearnHarness lesson without a speech subscription.

## Done when

- Selecting a Chinese word or short sentence offers **Read aloud** in the lesson selection menu. Playback starts on request and can be stopped.
- Kokoro v1.1-zh generates speech on the Windows desktop backend after model setup. Missing model assets produce an actionable error.
- Existing lessons and dictation remain usable. The model is kept outside source control.
- The Windows production build and Electron smoke checks pass, including selection and playback in an isolated lesson. Publish a draft pull request to the fork.

## Constraints

- Reuse the existing selection toolbar and the desktop server's trust boundary. Play without sending lesson text to a speech service or changing the lesson format.
- File-based model setup is documented in `docs/getting-started.md`.

## Open items

## Validation

- `npm run build` and `npm run typecheck` passed on Windows with Next.js 16.4.6.
- Full lint passed with one warning in an existing test. The focused playback, selection, history and dictation validation passed.
- `node scripts/smoke-provider-runtime.mjs` and `node scripts/smoke-server.mjs --electron` passed. The first standalone boot timed out during concurrent checks. It passed the same 30-second gate after packaging and the interactive probe finished.
- All 35 Windows Electron native and Kokoro route tests passed. Six failures observed in the broader Windows run also reproduced with the original main source. The CI workflow runs the broad suite on Linux.
- The repository packager produced an unpacked Windows x64 application. Its Electron executable ran the packaged server, which returned non-silent 24 kHz WAV audio from the real local Kokoro model.
- In Electron 44.9.3, the synthetic lesson offered Read aloud for Chinese, played a selected word, and stopped a selected sentence. There was no autoplay. English did not show this action and the lesson record remained byte-identical. The lesson renderer was restricted to loopback traffic.
